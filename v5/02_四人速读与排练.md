## 先用一分钟看懂整场

题目问：**AI已经参与研发AI，这是否会持续提高它研发下一代AI的能力？**

沿着研发链条走：减少迎合错误观点 → Agent交付可运行训练方法 → 激活引导和蒸馏改变目标模型 → 外部评测检验。再看其他研发对象：OpenAI的流程与记录、Google的训练算法、开放研究的策略与代码。最后分开两件事：结果能反馈到下一次尝试；基础模型后继研发能否持续增强。

全场只要守住三问：**改了什么？怎么知道改好了？改进能否帮助下一轮研发？** 主张是“局部自改进已有证据，基础模型后继研发的持续循环仍需检验”。DGM在限定代码系统中的自改不是零证据，不能用一个总括结论抹去。

**记住的结论：**这个问题有历史背景，今天值得研究是因为已经出现能检查的研发任务。重点看两家公司，是为比较模型变化与流程变化；其他案例补足不同改动对象。

**指图顺序：**历史问题 → 两种验证思路 → 四步目录 → 选案例理由 → Claude Opus4.8研究Agent／Qwen3.5-2B目标模型／评测器三个角色。

**三道追问：**

1. 为什么不先讲一遍Agent基础？课程已有基础，本场用具体工具、记忆和评测解释它在研发中的作用。

3. 什么叫减少谄媚？减少顺着错误观点迎合；目标也不是一味反对用户。

**交给B：**“下面看它怎样把一个想法变成可检查的实验。”已在07页稿末，不另加一段。

**最少准备：**看懂07页三个角色，能不用稿解释选择案例的理由；把自己的七页讲一遍并计时。

## B｜张程翔｜08—13页｜4分20秒

**记住的结论：**Agent交付能训练、能评测的方法，规则禁止利用评测数据、从研究Agent或更强模型蒸馏。引导教师与训练学生是两步；23.3%比较搜索条件，不是单个配方的效果。

**指图顺序：**一轮交付 → 外部记忆 → 引导教师 → KL训练学生 → 正常推理与评测 → 先讲教学分母、再讲真实数据。

**三道追问：**

1. 教师一定是更强的大模型吗？这里来自目标模型的引导版本。
2. KL降低是否就说明更安全？它只是训练目标；行为和能力副作用要由外部评测检查。
3. 23.3%是不是通过率？是改善空间。图二十有四种条件，本页选三项：公共数据SFT、自由构造数据SFT、不受限方法；截到前150个已评分方法，每条件一次运行。

**交给C：**“下一部分换一个环节，看Agent怎样协助把评测本身跑清楚。”已在13页稿末。

**最少准备：**能徒手讲清教师与学生两步；用50→70、最优100算一次40%。计时讲自己的六页；11页短片边播边讲，18秒包含在50秒内，失败就讲静态图。

## C｜赵金城｜14—18页｜3分15秒

**记住的结论：**OpenAI案例展示人审计划、可执行命令和可复用记录；Google展示算法优化。记录变好和模型权重变好是不同事情。

**指图顺序：**评测任务 → 计划与人审 → Runme三层记录 → 程序生成与评测 → 算子和总训练两个分母。

**三道追问：**

1. 谁批准开始执行？原文作者要求自己审阅计划；这是该作者流程的证据。
2. Runme的记忆存在哪？可回查的笔记、命令与结果，不能据此说Codex权重更新。
3. 23%和1%矛盾吗？前者对应一个kernel，后者对应完整训练，分母不同。

**交给D：**“接下来再看开放研究：Agent自己的策略和代码能不能改进？”可在18页后简短补一句。

**最少准备：**看懂审批原文和记录图；能说清两个百分数各自测什么。计时讲自己的五页。

## D｜曹天卓｜19—24页｜3分10秒

**记住的结论：** AgentEvolver把任务生成、经验复用与动作贡献归因接入强化学习，更新Agent策略参数；DGM在该实验中固定底模，修改工具与流程代码，再从版本档案选择候选继续探索。局部代码递归自改已有实例；持续研发更强的后继基础模型，还需要跨轮次检验。

**指图顺序：** 两种改进对象 → 全场研发地图 → 记录和Agent版本分别返回 → 新任务、同预算、多轮比较 → 明确回答题目。

**练习与追问：** 先看[六页口播与练习](11_D部分口播与练习.md)。组长答辩查[机制、例子与追问](10_D部分答辩备课.md)，包括DGM固定底模、档案多样性和基准分母。成员只需理解并练熟自己部分。

**三处别讲错：** 21页的两条返回箭头分别带回研究记录与修改后的Agent；DGM档案保留不同路线，并非每轮只留最高分。22页是本组提出的同预算、新任务、多轮比较建议，未开展。人类审批说明决策边界，不能单独否定系统发生了自我改动。

**收尾：** 23页先说已有特定任务中的局部自改，再说明基础模型后继研发还要观察多轮；24页进入提问。
