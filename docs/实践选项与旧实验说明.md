更新：2026-10-15。来源是本聊天最新讨论及用户最终决定。本页供全组与各自Agent理解，不是已经领取的实验任务书。

## 为什么考虑实践

我们想观察一个真实问题：改进后的Agent是否能继续改进自己，并更有能力完成下一轮AI研发？这能连接Anthropic的模型训练、OpenAI的研究工作流、AlphaEvolve的程序优化与DGM的代码自改。

晒提示词和制作过程，可以说明我们怎样使用Agent协作，但不直接回答这个研究问题；可留为方法附录。让Agent审查报告原文与标签的旧演示，也不是AI研发能力实验。

## 两条候选路线

| | 程序/系统自改 | 模型权重更新 |
|---|---|---|
| 改动对象 | 工具、规划、记忆、错误处理、候选选择等程序 | 模型参数；可考察参数高效微调 |
| 递归要看什么 | A₀产生A₁，A₁真实接棒继续产生A₂ | M₀研发M₁，M₁真实接棒研发M₂ |
| 固定什么 | 第一版可固定基础模型权重与评测规则 | 评测规则仍固定，并跟踪每代模型及训练设置 |
| 主要负担 | 模型推理、运行任务、程序版本与执行记录 | 上述负担加数据、训练、部署和能力保持检查 |
| 当前态度 | 资源允许时优先考察小规模可行性 | 暂不作为主路线；未决定也未启动 |

只把结果写进记忆，不自动说明研发能力提高；只微调一次，也不自动形成递归。两条路线都要看实际新版本做了什么。DGM证明了代码层自改值得研究，不应把它抹成“没有任何自改”；基础模型多代后继研发则是另一层问题。[DGM官方实现](https://github.com/jennyzzt/dgm)

“完全开源”选型应分别确认权重、推理/训练代码、数据及许可证。可考察公开完整模型流程的[OLMo](https://allenai.org/olmo)，但尚未选择具体模型；不能仅因权重可下载就声称所有训练资料公开。

## 已知资源与未知部分

2026-10-15对陈云海当前电脑的只读检查：Intel Iris Xe核显，约15.7GB系统内存，未检测到NVIDIA独显。不能据此推断其他成员没有独显，也没有核实其他设备。

当前电脑可考察小量化模型推理；是否能支持可靠的工具调用、自改代码及可接受速度，均未实测。它不适合在没有可行性依据时承诺递归训练模型。CPU量化推理可参考[llama.cpp](https://github.com/ggml-org/llama.cpp)，本页不要求安装。

## 如果有人愿意尝试，先做多小

先核设备、本人意愿及可用时间，再尝试一次：**读取任务结果 → 提出自身程序修改 → 实际运行新版本**。能运行不等于性能提高；只有这个过程可行，再决定是否扩大。

环境配置麻烦、模型不能可靠执行或时间成本过高，就停止并保留失败记录，不要求换云服务、购买设备或四人各补实验。沙盒是受控运行环境，研究问题和评价方法仍需另外明确。

正式轮次若发生，需区分搭底座时的外部Codex辅助和被测Agent自己的修改。人或更强外部模型介入修复时保留记录，不把外部完成的三版程序称为被测Agent的递归自改。

## 怎样选公开基准

优先考察AI研发任务，避免只因通用编程分数提高就宣称AI研发能力提高：

- [MLE-bench](https://github.com/openai/mle-bench#benchmarking)：机器学习工程任务。官方参考评测为每任务24小时、至少三次重复；Lite包含22项竞赛。不是当前小电脑可以直接承诺完成的一组任务。
- [RE-Bench](https://github.com/METR/RE-Bench)：AI研发能力任务，可按资源进一步检查具体环境。
- [DGM](https://github.com/jennyzzt/dgm)：可借鉴程序自改、候选保存与实验验证；完整仓库运行涉及模型API、Docker和编程基准环境，不能把“跑通仓库”当成已经获得研究结论。

若只选任务子集或缩短资源，沿用原任务评分并公开设置，称“选定任务上的对照”，不冒用完整榜单分数或排名。这些是任务能力基准，不是RSI认证。

有条件正式比较时，可保留原版、递归改进版，以及同预算重复尝试的原版；开发任务用于改进，最终比较任务不反馈给改进环节。各代冻结后在干净上下文中按相同预算比较，报告分数、失败、重复波动及自改成本。小范围结果只说明相应任务，不承诺必然提高。

## 旧24题、16题与分数的解释

旧任务是让Agent读公司材料，判断一句报告说法是否得到支持、是否夸大、与原文相反或无法判断。

- **24题开发集＝练习卷。** 原计划先看错误再改操作步骤；未完成运行，不是训练模型权重的数据集。
- **16题demo＝实际演示小测。** 两种事先写好的提示各做一次16题；没有通过24题错误分析得到候选方法。
- **16题补测＝原来想另准备没见过的题再测。** 不等于已经又做完一批，也不是现在的必做任务。
- **逐人实验＝旧方案要求每人自己跑Agent并留操作证据。** 已取消，不套用当前A陈云海、B张程翔、C赵金城、D曹天卓的讲述责任。

原始[score.json](../materials/practice/runs/demo/score.json)记载基线13/16、候选12/16，是与预设标签一致的数量；不是13/24、12/24。答案与任务没有真正隔离，部分标签有争议，因此不把它当事实准确率、研发能力分或改进成功证据。旧记录原样保存，个人实际操作不代签。
