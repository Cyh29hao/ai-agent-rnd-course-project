# Pre协作经验

版本0.1｜更新于2026-10-15｜适用于后续不同课程的汇报。

这份文档记录本人希望怎样与AI合作，以及当前智能体课程Pre暴露出的问题。**偏好已确认，最终课堂效果尚未验证。** 新课程的教学目标、评分与听众决定具体取舍。

## 一分钟看懂

1. **先审方案与样页，再制作全套。** 方案要让人看懂整场要讲什么、怎样讲、听完得到什么。
2. **主线清楚、有阶梯。** 从动机和具体问题出发，逐步进入机制与前沿，最后明确回答开头。
3. **PPT给人看，讲稿给人说。** 图、文字、多媒体都帮助理解；文字稿能直接说出口。
4. **技术、来源、答辩一起做。** 重要结论讲得出怎么来的，也经得起继续追问。
5. **少让成员做机械工作，多帮助本人真正掌握。** 首页能懂全场，每段有可以直接备课的材料。
6. **验收看实际效果。** 文件生成、导出成功或自动检查通过，各自只能证明有限的事情。

过去返工中最值得避免的情况：题目很大却陷入一个局部；页面堆了很多名词但缺少解释和衔接；把可选实践变成额外的大作业；材料生成后过早宣称完成。

## 1．默认怎样推进

### 先弄清任务，但不要让用户填写一长串表格

先读老师要求和已有材料，确认课程与具体选题、面向谁、时长、个人或小组、评分重点、截止日期。能从材料查到的先查；真正影响路线的信息集中问几项。尚未确定的写明暂定，继续做不依赖它的准备。

先用一句话复述研究对象和中心问题，避免被某个工具、案例或实验带偏。当前智能体课的公司案例、四人分工、页数和时间预算，均不自动沿用到别的课程。

### 第一份交付：一包能审的方案与样页

把下面这些放在一起交给用户审，减少来回确认：

- **题目、动机与一句话答案：** 为什么值得听，最后希望听众明白什么；结论暂定也可以，但必须能看出整场在论证什么。
- **目录与故事顺序：** 每段回答什么，前后怎样衔接，预估用时；标出主要图示、案例和媒体放在哪里。
- **关键内容依据：** 核实支撑路线的核心来源与数字，说明选这些案例的理由。细节尚待核实时如实标注。
- **几张有代表性的样页：** 一般覆盖开场或路线、机制解释、结果或比较、结尾中的几种。配对应口播、指图动作与转场，并看实际渲染。数量按内容决定。
- **需要用户决定的少数事项：** 例如选题取舍、整体视觉方向、某个实践是否值得做。制作工具等常规问题由AI处理。

此时应当能沿着目录把整场讲一遍，听得出逻辑；样页则证明这种讲法能落实到页面和口播。**等待用户认可后，再开始整套制作。** 方案包里明显的问题先自行修好，不拿未完成的工作反复索要确认。

### 认可后：完成全套，再按实际问题精修

沿认可的主线制作PPT、对应讲稿、来源与答辩材料；课程要求书面报告时再准备报告。内容、术语、页码与引用相互一致。一般措辞、布局和技术修复直接处理；若要换中心问题、重排整体路线或加入高成本实验，再交代原因并请用户判断。

## 2．内容怎样既有深度，又让人跟得上

### 让每段都推进同一个问题

目录体现问题的推进，而不仅是“背景、现状、挑战、展望”。开头说清动机和路线，段落之间告诉听众为什么换到下一步，结尾用具体答案回到开头。

历史适合用来解释今天的问题从哪里来；有真实的方法分歧时可以讲，不能为故事效果虚构学派对立。案例要说明选择理由、共同问题和各自补充的角度，数量服从解释需要。

先给听众一个具体任务或现象，再引入理解它必需的概念，随后解释机制、实验或结果，最后讨论适用范围。基础介绍的篇幅按听众调整；面对已学过相关内容的老师，用真实任务唤起知识，再进入细节。

### 留出解释空间

重要机制至少说清：谁或什么对象参与、做了什么、为什么可能有效、怎样测量结果。图中的箭头和百分数应当讲得出来。概念多就拆页、增加过渡、删掉次要案例，不能靠语速和堆字容纳内容。

需要体现前沿时，讲清新方法解决了哪个旧问题，以及它具体怎样做。不要只罗列论文和产品名，也不要只留下“尚有不足”式结论。

## 3．PPT、口播与多媒体怎样配合

### 页面为当时要讲的事情服务

一页通常承载一个主要意思，标题尽量说清问题或结论。按内容选择时间线、过程图、对比图、原文局部、实验曲线或现场演示，避免全篇重复同一种卡片排版。保持全场风格统一，让视觉变化帮助辨认内容层次。

文字、字号和图示要按实际投影可读性检查。保留必要技术细节，同时给听众看图的时间；复杂推导和延伸问题可以进入备份页。页数按讲述节奏决定，不把“少页数”当成好汇报的标准。

### 口播应当能直接讲

用完整自然的句子写清对象、动作和结果，概念首次出现时给一句解释。不要把PPT提纲原样扩写成抽象长句，也不要把制作备注和检查日志混进嘴上要讲的话。指图、翻页和操作提示另行标注。

表达示例，非具体研究结论：

| 含糊的说法 | 更容易理解的说法 |
|---|---|
| “构建多层次闭环，实现持续赋能” | “跑完这轮后，系统保存失败记录，下一轮据此更换方案。” |
| “相关结论仍缺少证据支撑” | “这项研究比较了两组结果，但没有继续测试改进后的系统，所以还不知道下一轮会怎样。” |

表达自然，也要保留有用的术语、条件和数字。每段结尾用一句话收住，再说明下一段为什么接着讲。

### 多媒体承担明确的解释任务

短视频、动画、可交互演示或实物，都应当帮助理解一个机制、现象或过程。选择形式时先想“它比静态图多解释了什么”，再决定是否制作。无需为凑形式每段都加视频。

明确区分真实录像、教学动画、公开素材和本组实验。确认素材出处与使用条件。播放前有引导，播放后有结论；准备播放失败时可用的静态讲法。可用时测试实际PPT播放和离线使用，不能只在制作页面里看一遍。

## 4．来源与答辩怎样一起准备

核心论点、关键数字和机制，应当能回到论文、官方技术资料或其他可靠原始材料；综述和二手解释用于寻找线索与理解背景。阅读后再引用，不把搜索摘要当成已经读过全文。访问不到就标明尚未核实。

数字说明测量对象、分母、比较基线、条件与方向；区分不同实验、不同指标和作者自己的推断。引用在页面上简洁可读，文献表格式一致，准备阶段保留页码、图表或章节定位。

每段同时准备几类自然追问：这是什么、为什么这样做、图和数字怎样得到、比较是否公平、结论能推广到哪里、与全场题目有什么关系。回答先给能直接说出的简短解释，再给机制、原文或图表作为深入展开。

新课程涉及健康问题时，要特别查清研究对象与研究设计，区分观察到的关联、机制解释和干预效果；没有研究支撑的健康建议不能写成已知结论。此处是研究与写作要求，具体事实需在选题后逐项查证。

答辩时间与精力按老师评分安排，不默认沿用当前课程的比例。答案需要本人理解；不能把生成一份问答册视为已经能够应答。

## 5．怎样让本人和组员省力

### 入口先解释，再链接

项目README或总览直接概括全场问题、各段内容与结论、分工和日期、材料用途、当前决定及下一步。重要部分各有一小段Summary，再提供详细链接。既方便快速理解，也能继续查细节。

文件用途一眼能认出，正式交付与正在修改的候选版本分清。保留原件，避免同时出现几套都自称“最终版”的材料。文件命名、Git操作和制作环境由Agent协助，不让成员先学一套工程流程才能改稿。

### 给每位讲述者一份短备课材料

包括本段要回答什么、关键概念与图、逐页自然口播、与前后段的交接、最可能的追问及出处。先帮助本人快速理解，再引导其讲一遍并练习回答，不要求先通读所有过程文件。

若是小组合作，各人负责自己的部分，组长熟悉并衔接全场。协调叙述用“组长”等角色称呼，真实姓名主要用于分工表。跨段变化一起商量，保留其他人的改稿。

提PR、交文件、直接反馈均可。交回时简单说改了什么、哪里希望讨论；不强制任务编号、固定分支名、修改条数、检查记录或整套模板。成员给自己的Agent的提示词应当说明内容目标和范围，并允许它直接做出可用改稿。

### 实践先判断是否值得

先问实践能回答全场的哪个问题，投入是否值得，设备和成员是否承担得起。若要做，先设计小而有解释力的尝试，说明比较方法和能得到什么结论；未验证的结果不能预写成提高性能。

使用AI制作汇报的记录可以展示真实协作过程；它不自动构成科学实验。不要为“体现实践”把主讲绑在另一项复杂任务上。实践是否必做，以本课程要求和用户决定为准。

## 6．怎样验收，避免提前宣布完成

下表是Agent的检查责任，不要求用户另填一张表。

| 要检查的事情 | 具体怎样看 |
|---|---|
| 主题与逻辑 | 按目录复述整场；每段推动中心问题，结尾给出答案；看后半段是否仍然完整、有解释空间 |
| 内容与来源 | 核关键论点和数字，检查图、来源、讲稿是否说同一件事；重要追问能找到原文 |
| 页面与媒体 | 导出后看实际页面，检查读图、字号、遮挡与拥挤；有条件时打开原生PPT、实际播放媒体 |
| 全套一致性 | 页面、口播、备注、答辩、文献及课程要求的报告相互对应，链接可用 |
| 时间与掌握 | AI先朗读或估算节奏，再由真人试讲、计时、练追问；分别记录，不互相替代 |

交付时说清哪些已验证、哪些还待本人或现场确认。条件不足的检查写明未做，不以此暗示已经通过。达到这一步的检查范围后停止无目的重复；若发现具体问题，再修正对应内容。

不承诺高分或“一把过关”。可以交付可审阅的阶段成果，但不能仅凭文件存在、代码检查或自评就宣布整场已准备完毕。工作跨会话时保存当前版本、用户已认可的决定、未完成项与下一步，让后续Agent能够接着做。

## 7．这份经验以后怎样更新

本次用户明确确认：先审主线、目录和样页后再制作全套；主线与阶梯、自然表达与媒体、技术来源与答辩、降低组员负担、实际验收，这五类要求全部保留。

后续遇到新反馈时，先弄清是通用偏好、某课程特例，还是尚待验证的方法。把可复用的做法补到对应章节；课程分工、实验分数和临时操作留在各自项目。若改变用户已经确认的工作方式，先说明变化并让用户决定。

维护时标明日期、发生了什么、因此调整了什么，以及效果是否已经验证。经验文档与启动提示词一起更新，再同步仓库在线副本。当前智能体课的后续精修、真人试讲和课堂反馈，都可以成为更新依据。
