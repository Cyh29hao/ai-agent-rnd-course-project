# 先理解这场汇报，再决定怎么改

## 一分钟讲给队友听

AI产业开始把自己生产的Agent用于研发：提出训练方法、执行评测、优化训练程序，甚至修改Agent自身代码。我们跟着这些工作走，最后问：这轮产出的方法、记录和改进后的Agent，能不能让下一轮研发更有能力？

Anthropic和OpenAI分别展开模型训练与评测流程，其他案例补足算法、策略和代码。选材依据是案例能解释什么，不是公司排名。

**全场三问：改了什么？怎么知道改好了？这次改进怎样帮助下一轮研发？**

听众应能解释一个真实训练机制，区分改动对象，并说明为什么要看下一轮；只记得“RSI尚未实现”不够。技术细节服务于这条主线。

## 六处容易说错的技术点

1. AAR中Claude Opus4.8研究，Qwen3.5-2B被训练，评测器分开。读取记录不等于研究Agent更新权重。
2. 教师是目标模型的引导版本，不是研究Agent或更强模型。教学图不补写未完整公开的KL方向、层号和系数。
3. 23.3%是前150个已评分方法的条件比较，不是蒸馏配方单独效果或通过率。图二十有四种条件，主讲选三种；每条件一次运行，同方法数不等于同总成本。
4. 65%属于Sonnet生成数据的另一实验，放备份30—31，不能混入主讲Qwen训练实验。
5. Google的23%对应kernel加速，1%对应总训练时间减少，分母不同。
6. DGM改Agent代码，AgentEvolver训练策略；有局部自改，也不能跳到基础模型多代后继研发。不能把所有案例称为提示词工程。
