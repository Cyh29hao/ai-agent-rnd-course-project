# 先理解这场汇报，再决定怎么改

## 一分钟讲给队友听

本组选题一采用行业应用案例研究，应用行业是AI研发。模型、工具和行动流程共同支撑Agent能力；这些研发环节开始由Agent参与：提出训练方法、执行评测、优化训练程序，甚至修改Agent自身代码。autoresearch把研究自动化，RSI进一步追问改进能否提高后续改进能力。我们跟着这些工作走，最后问：这轮产出的方法、记录和改进后的Agent，能不能让下一轮研发更有能力？

Anthropic和OpenAI分别展开模型训练与评测流程，其他案例补足算法、策略和代码。选材依据是案例能解释什么，不是公司排名。

**全场三问：改了什么？怎么知道改好了？这次改进怎样帮助下一轮研发？**

听众应能解释一个真实训练机制，区分改动对象，并说明研发正反馈为什么值得重视、又受什么约束；只记得“RSI尚未实现”不够。技术细节服务于这条主线。

## 七处容易说错的技术点

1. RSI是Recursive Self-Improvement。研究自动化可服务于递归自改，但自动跑完实验不等于研究者本身更强；局部Agent代码自改也不等于前沿基础模型多代自研。正反馈可能加速研发，不能直接画成必然指数增长。
2. AAR中Claude Opus4.8研究，Qwen3.5-2B被训练，评测器分开。读取记录不等于研究Agent更新权重。
3. 教师是目标模型的引导版本，不是研究Agent或更强模型。教学图不补写未完整公开的KL方向、层号和系数。
4. 23.3%、16.5%、6.0%、2.9%是前150个已评分方法下四种搜索条件的比较，不是一个模型逐步加模块的效果或通过率。每条件一次运行，同方法数不等于同总成本；KL条件完整运行峰值18.7%不能替代共同横轴的16.5%。
5. 65%属于Sonnet生成数据的另一实验，放备份30—31，不能混入主讲Qwen训练实验。
6. Google的23%对应kernel加速，1%对应总训练时间减少，分母不同。
7. DGM改Agent代码，AgentEvolver训练策略；有局部自改，也不能跳到基础模型多代后继研发。不能把所有案例称为提示词工程。
