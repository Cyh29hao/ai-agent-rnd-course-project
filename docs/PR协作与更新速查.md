# 怎么交改稿、怎么看更新

我们用GitHub是为了方便分享和讨论，大家用顺手的方式合作就好。

## 改好了怎么交

会用PR的话，在自己的分支上修改，完成后提一个PR。PR可以理解成“把我的改稿拿给大家看看”，能看清改了哪里，也方便讨论和接着修改。

**标题说清是哪一部分，正文简单说改了什么就够了。** 比如“B部分：把蒸馏的讲法改顺一点”。有需要大家帮忙判断的地方，顺手写一句。模板可以删，不必填任务编号、提交哈希、检查清单，也不限一次改多少。

可以直接改文字和自己的PPT页，不一定先写提案。不熟悉PR就把文件发给陈云海，或者直接提意见，也一样可以参与。涉及别人的部分，打个招呼一起商量；陈云海负责最后合稿和衔接。

## 让自己的Codex处理操作

```text
帮我把这次改稿交回仓库。先保留我和其他人的现有修改；用合适的分支提交，提一个PR，简单说明改了哪一部分、哪里想请大家看看。分支名字和说明不用复杂，按内容来即可。若暂时不能提交，就保留文件并告诉我可以把哪些文件交给组长。不要替我合并到全组主稿。
```

## 想看最近改了什么

- 看全组最新安排：[README](../README.md)。
- 看重要变化：[更新速览](../CHANGELOG.md)。
- 看大家正在改什么、留言讨论：[PR列表](https://github.com/Cyh29hao/ai-agent-rnd-course-project/pulls)。
- 想细看某一句怎么变了：在PR点`Files changed`，或打开文件看`History`。

本地旧文件不会随网页自动更新，可以让自己的Codex帮忙同步，记得保留自己正在写的内容。

还没进私有仓库的同学，把GitHub用户名或主页链接发给陈云海，收到邀请后接受即可。
