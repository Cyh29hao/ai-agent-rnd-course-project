## 内容评估

### 建议再斟酌的地方

- **19页DGM的版本保留方式。** “保留表现更好的候选谱系”容易使人以为只留高分版本。官方说明强调不断扩展的版本档案和多条探索路径，可以从档案中的不同版本继续分支。建议改为“将候选版本与评测结果保存到档案中，从不同版本继续探索”。原来稿先保持不动，留待审阅决定。
- **22页实验能说明多少。** “这样能确认”比原稿更强。使用新任务、等预算和多轮比较有助判断泛化与研发效率，有限测试不能保证覆盖所有场景。建议“这样有助于判断”。这一页是比较方案讨论，本组尚未执行该实验。
- **23页结尾可以再明确半步。** 可先回答“已有特定任务上的局部自改”，再说明还要跟踪改进后的研究系统能否持续提高基础模型研发能力。基础模型后继研发是本报告关注点；RSI也可讨论系统或代码层，不宜用权重是否改变一条标准否定所有局部自改。
- **时间需要本人试讲。** 文中仍是190秒设计预算，未由这次收稿验证。40秒里同时讲两个新系统可能偏紧，可以把详细机制放入答辩材料。

1. AgentEvolver怎样生成任务、复用经验、对动作贡献分配奖励，训练的策略具体指什么。
