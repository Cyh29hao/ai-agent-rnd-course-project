# 两段媒体分镜与证据边界

## A. Anthropic 方法泳道，10秒

2帧，每帧5秒，静音，1920×1080。两帧均为**依据公开论文方法重绘的示意**，不表示小组或公司真实运行画面。

1. 0–5秒：研究代理提出 mini-paper 和代码，工具侧审查并训练，隔离评分返回反馈。强调交付物经过工具而非文字循环。
2. 5–10秒：检查点、评分和共享记录回到下一轮研究代理；人的目标与实验边界始终在系统外。图上标明“方法示意”。

核对来源：`S2`，论文 §2–3，见 `../sources/00_一手来源定位包.md`。与主讲第5页的开放权重主实验对应，不能混成生产级检查点实验。

## B. 真实公开日志重排，18秒

3帧，每帧6秒，静音，1920×1080。**这是根据已保存的 `practice/runs/smoke/actions.jsonl` 与 `output.json` 重排的文字动画，不是UI录屏，也不是按真实运行速度播放。** 日志前四个动作是事后补记，精确发生时间不可得；画面只给步骤，不给伪造的秒表或耗时。第五条校验有实际时间戳。

1. 0–6秒：读取题目和协议；首读 schema 路径错误，后来找到 `practice/schema.json`。保留这个真实小失误。
2. 6–12秒：打开 OpenAI 官方网页，定位 `Running evaluations with Codex`，查到作者要求先写计划并等待审阅批准。
3. 12–18秒：写 `smoke-01` JSON，标签 `supported`，定位 `T1#T1-run-evals-plan`；真实校验返回 `VALID smoke-01 supported T1#T1-run-evals-plan`。字幕注明“制作代理资格探测；非四人实践”。

原始数据：`../practice/runs/smoke/actions.jsonl`、`../practice/runs/smoke/output.json`、`../practice/runs/smoke/metadata.json`。公开网页：[OpenAI 原文](https://developers.openai.com/blog/automating-repetitive-work-at-openai-with-codex)。这段只证明资格探测有工具读取、来源核对、产物与校验，不证明候选优于基线。

## 数据实验状态

`practice/runs/demo/freeze.json` 记录两个新上下文各一次性处理16题、每批最多10次工具调用，和学生逐题独立会话协议不同；这批演示题与答案在共同工作区可见，没有OS隔离，采样设置不可固定。媒体只取独立 smoke，不把该 demo 说成盲测。任何 demo 成绩须等待两套真实输出与脚本评分后再写上幻灯片。

## 复现

在本目录上一级运行：`python _build/build_media.py`。脚本重读实际 smoke 日志、校验动作及标签，重建两个关键帧 PPTX、导出每帧 PNG 和 H.264 MP4；用独立 PowerPoint COM 实例，不关闭现有 Office。生成后检查 MP4 轨道、尺寸和时长。若 PowerPoint 导出失败，PPTX和PNG为静态替代。
