# 第一次真实 Agent 运行

目标：本人亲自让 Agent 读取一手网页、核对一个主张、保存 JSON 并运行校验。约10—20分钟是操作安排，实际耗时由本人记录。这里不要求购买新API，也不把人工样例当成Agent运行。

## 1. 进入能够操作文件的环境

使用你本人已有的 Codex 桌面版或课程 OpenClaw 工具环境。本教程的参考入口是 Codex：在本地项目中打开汇报包目录，再从该项目开始一个新聊天。官方说明区分本地项目文件访问与普通 ChatGPT 项目，普通聊天里单纯输入本机路径不会让它读取文件。[官方项目与聊天说明](https://learn.chatgpt.com/docs/projects?surface=app)

先确认该新聊天可以读取 `practice/schema.json`。之后再确认可以访问公开网页。看不到文件时，先修正项目文件夹；看不到网页工具时，准确记录工具条件，不能声称已核对原文。模型名称从你实际使用的选择器或环境配置记录；未显示则写“未知”，不能把本包示范的`gpt-6-sol`自动当成自己的模型。

若使用另一台电脑，将收到的汇报包放在自己的稳定目录，选择那份实际存在的文件夹作为本地项目。教程和下面提示使用相对路径，适用于不同磁盘。成员C保管独立最终测试时，要使用自己单独的私有目录；新聊天本身不提供操作系统级文件隔离。

## 2. 准备你自己的记录目录

在汇报包目录的PowerShell运行下列命令，将`your_id`改为本人可识别的ID，例如拼音。该命令只准备记录目录，不启动Agent，不产生答案：

```powershell
python practice/prepare_student_run.py --id your_id
```

只给被测Agent这四份规则与输入：

- `practice/protocol_baseline.md`
- `practice/schema.json`
- `practice/smoke/claims.json`
- `practice/smoke/sources.json`

不要给`smoke/gold.json`、`smoke/example_output/`、制作代理的既有答案或评分结果。这样限制提示输入仍不等于真正隔离测试，本题只做工具资格探测。

## 3. 可直接复制的任务提示

替换下列提示中的两处`your_id`，然后发给该新聊天：

```text
当前工作目录是我打开的汇报包。请执行一次真实来源核查，而不是直接凭记忆给答案。

只读取这些规则与输入：practice/protocol_baseline.md、practice/schema.json、practice/smoke/claims.json、practice/smoke/sources.json。不要读取任何gold.json、example_output、已运行输出、评分或其他Agent的答案。只在practice/runs/students/your_id/下面写文件。

请先实际读取上述四份文件，再使用本环境可用的网页/浏览工具打开来源包中的OpenAI官方文章，查找Running evaluations with Codex目标节，核对Codex先写计划、等待作者批准的主张。若网页工具不存在或访问失败，报告真实障碍，不编造已读原文或工具动作。

按protocol_baseline.md的四类规则判断smoke-01。把符合schema.json七个字段的单个JSON对象，保存为practice/runs/students/your_id/outputs/smoke-01.json。保存原始判断，不读取标准答案迎合分数。

实际运行：python practice/validate.py --input practice/runs/students/your_id/outputs/smoke-01.json --claims practice/smoke/claims.json --sources practice/smoke/sources.json

将原始公开动作记录在同目录的actions.jsonl：工具、实际读取文件/网址、结果、失败。若精确发生时间没有记录，使用recorded_at并写明事后补记，不能虚构执行时间。保留原始输出和真实校验结果，不保存隐藏推理、不复制身份或时间。结束时报告你做了哪些工具动作、输出在哪里、校验实际结果、哪些环节尚未确认。
```

若有权限提示，按你自己的任务范围授权可逆文件读写和公开网页读取即可；未经本人允许的外部发消息、发布或删除不属于这项练习。执行完后保存会话中的公开工具记录截图或原始文件，不能由另一个人补写为你的操作。

## 4. 亲自验证，而不是只相信一句“完成”

再次运行上面的`validate.py`命令，读取实际返回值。

| 看见什么 | 可以认定什么 | 仍要检查什么 |
|---|---|---|
| 文件实际读到了 | 路径和文件访问可用 | 文件是否是本轮正确输入 |
| 官方网页工具调用有结果 | Agent确实取得公开来源 | 节号和原文是否支持主张 |
| JSON校验返回`VALID`且退出码0 | 七个字段、枚举和位置编号结构有效 | 不能据此认定标签与来源语义正确 |
| 另一位成员打开原文并核对 | 有一次真人来源复核 | 标签分歧仍应说明依据和裁定 |

**不要先看金标。**让另一位成员打开文章目标节，独立核你的出处与标签，再比对标准答案。此时由评分人读取`smoke/gold.json`即可；被测Agent无需读取它。

## 5. 本人填写记录

`prepare_student_run.py`会创建`run_manifest.json`和`本人记录.md`。你本人填写实际模型、工具条件、起止时间、平台、产物路径，以及你接受或修正的一条结论。它不会替你填已发生的动作，不自动签名。缺失采样参数或成本写`unknown`。

这一题完成只证明工具资格探测，不证明候选改进、完整实验、独立holdout、四人成果或RSI。之后A做来源卡、B做基线、C做独立评测、D做候选改动；这些只是角色选择，具体成员由你们确认。每位至少留下本人一次真实任务及人工决定，再更新报告个人段落。

## 6. 常见失败

- **找不到文件**：检查当前项目是否为汇报包；相对路径从该目录解释。不要把`schema.json`误放在包根，它在`practice/`。
- **没有网页工具**：本次条件尚不足以核一手原文，保留文件和错误。若环境有公开网络读取工具，可实际读取文章目标节；纯聊天回答不能补充成网页调用日志。
- **字段或枚举错误**：保留原始错误JSON；将校验报错交给Agent修格式，另存修正版并记录修复。不要因格式改动顺手改事实标签去追分。
- **标签和金标不同**：先核原文和类别边界；不能把金标天然视为正确。当前16题制作演示已经发现这样的争议，应保留分歧并由人裁定。
- **同一对话被CLI恢复失败**：不要把桌面版正在写入的会话再交给另一进程恢复。新任务采用独立新聊天，不复用这个仍活动的对话。先留下原始错误，不能反复重试后声称启动成功。
