## 这场汇报讲什么

我们关注一件正在发生的事：AI公司开始让智能体参与研发下一代AI——提出训练方法、执行评测、优化训练程序，甚至修改智能体自己的代码。这些工作已经做到了哪一步？改进后的系统，能不能接着把下一轮研发做得更好？

全场按 **“问题从哪里来 → 智能体怎样参与研发 → 它能否继续改进自己”** 展开。重点用Anthropic讲模型训练，用OpenAI的公开工作流讲评测，再用Google及开放研究补上算法、策略和代码层面的改进。选择这些案例，是为了把不同研发环节连起来看。

听完应当能回答三个具体问题：**改了什么？怎么知道改好了？这次改进能怎样帮助下一轮研发？** [完整主线与内容地图](docs/项目主线与内容地图.md)

## 课程怎么考核、我们怎么准备

按已核对的第一讲要求：**2—4人自由组队；答辩50分，报告50分；小组选1人参加答辩，每位成员分别撰写个人报告。** 个人报告应体现自己负责的内容、做法和体会，组内报告应有差异。依据为第一讲课件第5页及2026年9月14日第一节录播00:14:33—00:15:53；[Canvas原课件](https://oc.sjtu.edu.cn/courses/93028/files/13851378)可供核对。

**本组暂定由组长参加答辩，组长会熟悉并准备全场内容。** ABCD保留为内容分工。成员交回自己的改稿后，由AI继续润色讲稿，必要时联动修改PPT，整理成供成员理解、练熟的基本定稿；来源核对和全场答辩材料由AI集中补齐，不再要求成员另交一套技术说明或问答。

集中制作的答辩材料要让组长能够理解、查阅并直接练习回答，包括：

- **讲得懂的解释：** 核心概念、方法步骤和关键图，能说明为什么这样做、结果意味着什么。
- **查得到的依据：** 重要结论与数字对应的原文链接、图表或章节位置，说明比较条件、分母和适用范围。
- **答得上的问答：** 本段可能被问到的问题、可直接说出口的回答，以及进一步追问时怎样展开；拿不准的地方明确标出来。
- **能接上全场的材料：** PPT、文字稿与问答保持一致，说明本段与题目、相邻部分和最终结论的关系。

**成员负责看懂、练熟自己的部分，反馈实际讲不顺或不明白的地方；AI负责后续精修、联改、核源和答辩材料整理；组长熟悉全场并练习答辩。** 基本定稿后按具体问题修正，避免反复给成员追加准备任务。现场仍按小组选一人答辩准备。

**每人还需分别完成自己的50分报告**，可参考共用资料，结合本人实际负责的内容独立组织与撰写。教师报告模板、具体提交要求、日期和答辩时长尚待确认。

## A—D分别讲什么、接下来怎么改

### A｜为什么要研究“AI研发AI”？（01—07）

从Good关于“机器设计更好的机器”的设想讲起，简要带到两种思路：先证明修改有益，或让系统通过实验寻找更好的方案。随后落到今天的产业研发：为什么值得研究，为什么重点选Anthropic和OpenAI，Google和开放研究又补充了什么。最后用“减少模型谄媚”的任务，分清研究Agent、被训练的模型和评测器，把问题交给B。

**精修重点：** 开场有故事，动机讲具体；让听众知道接下来为什么看这些案例，并提前埋下结尾要回答的问题。[A的详细建议](docs/分工与衔接.md#a组长开场有故事问题能落地)

### B｜智能体怎样提出并验证训练方法？（08—13）

跟着Anthropic案例走完一轮研究：提出假设、实现方法、训练、评测，再根据记录继续尝试。技术重点是激活引导与蒸馏：目标模型经过引导后充当教师，学生通过训练学习教师的输出分布，之后再评测学生的表现。KL在这里衡量两者输出分布的差异，用于指导训练；23.3%则是方法搜索条件比较中的结果。

**精修重点：** 把训练机制讲成连续过程，讲清谁在研究、谁的参数变了；23.3%不能直接当成某个蒸馏配方的效果。[B的详细建议](docs/分工与衔接.md#b张程翔把方法怎样改变模型讲清楚)

### C｜研发中的评测和程序优化怎样交给智能体？（14—18）

先看OpenAI研究人员公开的评测工作流：Codex提出计划，人确认后执行，Runme保存命令、结果与决策，下一次可以接着做。再看Google的AlphaEvolve如何生成程序、运行评测、保留较好的候选。由此理解智能体除了提出训练方法，还能怎样改善研发流程和训练程序。

**精修重点：** 用具体任务说明每个工具带来了什么；讲清kernel加速23%与总训练时间减少1%的区别，并接到D的“智能体自身能不能改”。[C的详细建议](docs/分工与衔接.md#c赵金城把流程价值和算法收益讲具体)

### D｜改进了模型或程序，就算递归自我改进了吗？（19—24）

用AgentEvolver的策略训练和DGM的代码自改，进一步看智能体自身可以怎样变化。DGM中，修改后的智能体还能继续参与探索，这是值得展开的局部自改。全场的回答是：已有系统能在特定任务里改善模型、程序或Agent；要谈持续的递归研发，还要看改进后的研究者能否一代代接手研究，持续做出更好的成果。

**精修重点：** 把已经做到的事情讲扎实，把“下一轮谁来研究、靠什么变强”讲具体。结论与开头呼应，给听众一个能复述的答案。[D的详细建议](docs/分工与衔接.md#d曹天卓比较改动对象具体回答递归问题)

## 怎么一起改

按自己顺手的方式做就好：直接改稿、编辑自己的PPT页面，或者让AI Agent协助都可以。交回时说清改了哪一部分、还有什么想讨论，组长最后统一合稿。涉及相邻段落时，和对方一起看一下过渡、术语和结论是否接得上。

**会用PR就把改稿提上来，方便大家看差异和讨论；不熟悉PR，直接发文件或提意见也可以。** 不要求固定分支名字、任务编号、修改条数或填完整套模板。Git操作可以交给自己的Codex处理；注意保留其他同学的修改。

**看最近变化：** [更新速览](CHANGELOG.md)记录全组需要知道的安排和重要修改；[大家的PR](https://github.com/Cyh29hao/ai-agent-rnd-course-project/pulls)能看改稿差异、留言讨论。网页更新后，本地文件需要另行同步，可以请自己的Agent保留现有修改后处理。[简单协作说明](docs/PR协作与更新速查.md)

## 关于实践

**实践是可选项，目前未启动、未纳入主讲，也未安排给任何人。** D若愿意且设备合适，可以再讨论；难做就取消，各段初稿照常推进。

我们讨论过两条路线：一条是固定模型，让智能体修改自己的工具、策略或代码，再由改后的版本继续尝试；另一条是训练出改进后的模型，再让它参与下一轮研究。前者更适合作为小规模尝试，后者对算力和实验设计要求更高。若开展，应在固定任务与可比较的条件下看结果，重点检查“改后的系统是否真的接手下一轮”。

大家使用Agent协作制作这次汇报的过程，也可以如实介绍；它与上述自我改进实验分别说明。旧演示和练习不再是必做任务。[两条实践路线、算力判断与旧实验解释](docs/实践选项与旧实验说明.md)
